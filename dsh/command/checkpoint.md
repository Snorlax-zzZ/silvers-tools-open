# /checkpoint — 归档当前会话状态

DSH执行，对用户称用户。

> **为什么不是 `/compact`**：compaction 那一刀本身要吃掉「全部历史 + 摘要」，跟普通调用一样疼，而且压缩后 prompt cache 全断。真正省 token 的姿势是**主动归档成精简文档 → 开新会话 → 加载续命**，省的是之后每轮的累积 input。完整算账与设计取舍见 `<CHECKPOINT_TOOLS>/cc/command/checkpoint/README.md`（本文件不复述）。
> **存档位置**：`~/.dsh/checkpoints/<项目目录名>/`，全局存放、按项目分子目录，**零侵入项目目录**（不用改项目 `.gitignore`）。

## 参数

从用户消息里取参数（`/checkpoint` 之后的文字）当**要写入 / 覆盖的文件路径**；为空则走步骤 2 的默认判定。项目根一律取**当前 cwd**。

## 执行步骤

### 1. 计算路径

- **项目目录名**：当前工作目录绝对路径，把 `/` 替换成 `-`
  - 例：`/Users/<USER>/Documents/chat-app` → `-Users-<USER>-Documents-chat-app`
- **checkpoint 根目录**：`~/.dsh/checkpoints/<项目目录名>/`，不存在就 `mkdir -p`

### 2. 决定要写哪个文件（按优先级）

| 优先级 | 条件 | 行为 |
|---|---|---|
| 1 | 用户消息里传了路径（非空） | 用这个路径（覆盖更新） |
| 2 | 你（DSH）在**本次对话**里记得「当前维护的 checkpoint 文件路径」（之前 load 过或创建过） | 用这个路径（覆盖更新） |
| 3 | 都没有 | 新建 `YYYYMMDD-HHMMSS-<slug>.md`；同秒已存在则追加毫秒 `YYYYMMDD-HHMMSS-NNN-<slug>.md` |

**文件名 slug 规则**（用户在列表里靠它一眼识别任务）：

- 从任务标题里提炼 **8-15 个中文字**的核心描述
- 去掉标点、空格、括号、引号，只留中文字符
- 例：标题「设计并实现 checkpoint 命令体系（长任务接力）」→ slug `设计checkpoint命令体系`
- **首次创建时定死，后续覆盖更新不改文件名**（避免上下文里记的路径失效）
- 任务方向变了 slug 可能不贴切，但 frontmatter 的 `title` 会随更新刷新，**列表展示用 title 而不是 slug**（slug 只负责文件名肉眼识别）

### 3. 写入文档

**前置（强制）**：写入前必须先跑一次 `date '+%Y-%m-%dT%H:%M:%S%z'` 拿当前真实时间。`updated_at` 必须用这次跑出来的值，**禁止从对话上下文复用任何已有时间戳**（包括 frontmatter 里原有的 `updated_at`、之前跑 date 的输出、对话里出现过的时间引用）。长会话里的时间戳极易漂移（曾出现 2h12m 偏差），这是硬约束。

**Frontmatter**（每次都要写/更新）：

```yaml
---
project_root: <当前工作目录绝对路径>
created_at: <首次创建时填，复用则保持不变>
updated_at: <每次写入都刷新为当前 ISO8601 时间，含时区>
title: "<一句话任务标题，从对话中提炼，10-25 字>"
status: in-progress
---
```

**正文推荐结构**：

```markdown
## 任务目标
（1-2 句话，用户启动这个任务时想要的最终结果）

## 当前进度
（做到哪一步、下一步要干啥，3-5 行）

## 🚨 已踩过的认知陷阱（强制段，新 session 必读）
列出本轮**走错并被纠正**的认知误区。新 session 拉起来不读这段，极容易再走同一条弯路。每条三段式：
- **陷阱**：（描述误区，比如「把 X 概念当成 Y 概念」「以为 A 必须有 B」）
  - **真相**：（澄清后的正确认知）
  - **来源**：（哪句话 / 哪个文件 / 哪次澄清纠正的，含时间戳）

真没踩过就写「无（任务直线推进）」。**不要为了凑段编**。

## 关键决策（强制段，三段式 决策 | 理由 | 来源，第四项按需）
- **决策**：（做了什么决断，如「采用 X 方案 / 删 Y 模块 / 选 Z 库」）
  - **理由**：（为什么这样，跟备选方案对比的核心差异点）
  - **来源**：（用户某次拍板 / 某轮 verify 反馈 / 实测发现，含时间戳）
  - **放弃的备选**：（认真比较过并否掉的方案 + 否掉原因，防止下一轮又被重新捡回来提）
    **没有实质备选就不写这一项，不要为了凑格式编假备选**——只有一条自然路径的任务，省掉它才是对的。

## 关键发现（可选段，技术事实 / 位置）
- xxx 文件 line N 有竞态条件
- 上游 schema 字段类型严格性等非平凡事实

## Follow-up 清单（强制段，按触发条件分层）
没 follow-up 时写「无」占一行，段也要保留。

### P0 - 主链路阻塞
（当前主任务收口前必须完成的）

### P1 - 主链路一并验证
（联调 / 主流程跑通过程中要 verify 的）

### P2 - 主链路完成后清理
（功能跑通后再做的）

### longterm 架构债
（评估后做的，可能跨发布周期）

每条明示**触发条件**（什么时候做）+ **实施位置**（在哪改）。

## 联调步骤（可选段，任务真有联调 / 验证流程才写）
具象到能直接照着跑：
1. 启动命令：`<完整命令，含工作目录>`
2. 准备数据：认证信息 / 测试租户 / fixture 数据来源
3. 调用模板：`<curl / 测试入口完整命令>`
4. 验证方式：`<diff 命令 / 看日志关键字>`

## 引用（不复述内容，只列路径）
- 设计文档：docs/architecture/xxx.md
- 关键 commit：`abc1234` <description>
- 已读关键文件：src/xxx.py（line N 是核心）

## 下一步建议
- 立即要做：xxx
- 可能要用的 skill：test-driven-development
- 待确认问题：xxx

## ⚠️ AI verify 边际效用提醒（可选段，经过多轮 AI 审的任务才写）
- 已做：<某某工具> 各 N 轮，产出报告 `xxx.md`
- 不要再做：第 N+1 轮 AI verify 边际效用极低（典型征兆：上一轮 BLOCKER 全修完，只剩 NIT）
- 下一步建议：真实流量 / 联调驱动，跑出真问题再修，别继续 AI 审
```

### 4. 记住当前文件路径

写完**在对话上下文里记住「当前维护的 checkpoint 文件路径是 `<完整路径>`」**。同一会话内后续的 `/checkpoint` 和 `/task-done` 默认对它操作。

### 5. 汇报用户

```
✅ 已保存到 `<完整路径>`（约 X.X k token，覆盖/新建）
```

## 字段使用指导

上面的字段**只是参考结构，不是必须照搬的模板**。

**写作核心**：让另一个全新的会话读完能在 5 分钟内知道「做到哪 + 下一步干啥 + 别重走哪些弯路」。

按任务情况调整：简单任务可能只要「当前进度 + 下一步」；复杂调试可能要展开「已排除路径」；多模块改动可能要加「涉及文件清单」。

你自己判断哪些段该留、该详细、该砍掉。智商在线，别照搬。

## 写作铁律

- ❌ 不要把读过的文件内容粘贴进来
- ❌ 不要复制 diff、commit 信息、PR 描述
- ❌ 不要把已经写在 plan / ADR / 设计文档里的决策再抄一遍
- ✅ 只记结论不记过程
- ✅ 死路也要记（避免下一轮再走）
- ✅ 用项目术语（参考项目根的 `AGENTS.md` / `CLAUDE.md` 里的语言）

## 体积约束（硬性）

目标 **3-5k token**（约 2000-4000 中文字，视 tokenizer 而定）。**超过 5k 必须砍**——写得跟 `/compact` 摘要一样大就失去意义了。

## 沙箱提示（DSH 特有）

`~/.dsh/checkpoints/` 在**工作区之外**：`workspace-write` 档下写它会被沙箱拒绝。遇到拒绝就按沙箱升权流程申请一次更宽档位（`read-only` → `workspace-write` → `danger-full-access` 是封闭阶梯，只能往更宽的方向走），或让用户用 `/permission` 切到含 full-access 的预设。**不要**为了绕开沙箱把 checkpoint 塞进工作区（会污染项目的 git）。详见同目录 `README.md` 的权限章节。
